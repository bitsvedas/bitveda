What is an OS?

A program that acts as an interface between the user/software and computer hardware. It manages resources and provides a platform for applications.

Process Active Entity (In execution in RAM)
Program Passive Entity (Stored on disk)

Types of Operating Systems

  • Batch OS: Processes similar jobs in groups (batches) all at once without direct user interaction during execution.
  • Multiprogramming OS: Keeps multiple programs in the memory so the computer can switch between them and keep the processor busy.
  • Time-Sharing / Multitasking OS: Allows many users or tasks to share the processor at the same time by splitting CPU time into tiny pieces.
  • Multiprocessing OS: Uses two or more processors (CPUs) inside a single computer system to run tasks faster and do parallel computing.
  • Distributed OS: Connects independent computers over a network so they work together and look like a single big computer.
  • Network OS: Runs on a server to manage user data, security, printers, and traffic across a local network.
  • Real-Time OS (RTOS): Designed for extreme time-critical jobs (like car airbags or factory robots) where a delayed response can cause a failure.
  • Mobile OS: Built specifically to manage touchscreens, wireless data, and apps on phones and tablets.

PCB (Process Control Block)

Also called Task Control Block. A data structure containing information about the process (State, Program Counter, CPU registers, Memory info).

UNIX System Calls

  • fork() : Create a new child process
  • wait() : Parent waits for child to finish
  • exec() : Replace process with new program
  • abort() : Forcefully terminate process

Critical Scheduling Problems

🚜 Convoy Effect

Occurs primarily in FCFS. When a single heavy process with a massive CPU burst arrives first, all smaller, faster processes behind it must wait.

Result: Drastically increases average waiting time and lowers CPU/device utilization.

💀 Starvation & ✅ Aging

Starvation: Occurs in SJF and Priority Scheduling. Low-priority or long processes wait indefinitely because shorter/higher-priority processes keep continually arriving.

Aging (The Solution): Gradually increasing the priority of processes that sit in the ready queue for a long time.

First Come First Serve (FCFS)

Non-Preemptive

The simplest algorithm. The process that requests the CPU first is allocated the CPU first. It is implemented using a FIFO queue.

Pros:

Simple, easy to write and understand.

Cons (Convoy Effect):

If a massive process arrives first, all small processes behind it must wait a long time, drastically increasing average waiting time.

Shortest Job First (SJF)

Non-Preemptive

Associates each process with the length of its next CPU burst. Use these lengths to schedule the process with the shortest time.

Pros:

Gives the minimum average waiting time for a given set of processes. (Optimal algorithm).

Cons (Starvation):

If shorter jobs keep arriving, a long job may never get to execute (Starvation). Hard to predict next CPU burst length.

Shortest Remaining Time First (SRTF)

Preemptive Version of SJF

If a new process arrives with a CPU burst length less than the remaining time of the currently executing process, preempt (kick out) the current process and execute the new one.

Pros:

Better average response time than non-preemptive SJF.

Cons:

High context-switching overhead. Starvation for longer processes is still a major issue.

Round Robin (RR)

Preemptive

Designed especially for time-sharing systems. Every process gets a small unit of CPU time (Time Quantum). After this time, it is preempted and added to the end of the ready queue.

Key Fact:

If there are N processes in the ready queue and time quantum is Q, no process waits more than (N-1)*Q time units before getting CPU again.

Performance Rule:

  • If Quantum is too large ➔ Behaves like FCFS.
  • If Quantum is too small ➔ Context switch overhead dominates (very slow).

Priority Scheduling

Preemptive or Non-Preemptive

A priority number (integer) is associated with each process. CPU is allocated to the process with the highest priority (usually smallest integer = highest priority).

⚠️ Major Problem: Starvation

Low priority processes may never execute if high priority processes keep coming.

✅ The Solution: Aging

A technique of gradually increasing the priority of processes that wait in the system for a long time.

What is a Deadlock?

A situation where a set of processes are blocked because each process is holding a resource and waiting for another resource acquired by some other process.

4 Necessary Conditions (All must hold simultaneously):

1 Mutual Exclusion:

At least one resource must be non-shareable.

2 Hold & Wait:

Holding a resource while waiting to acquire others.

3 No Preemption:

Resources cannot be forcefully taken away from a process.

4 Circular Wait:

P0 waits for P1, P1 waits for P2... Pn waits for P0.

Banker's Algorithm (Deadlock Avoidance)

Avoidance > Prevention

The OS simulates allocation to check if it leads to a "Safe State". If Safe, resources are granted. Let's solve the example from the image:

Process Max Need Current Holding (Allocated) Remaining Need (Max - Curr)
P0 10 5 10 - 5 = 5
P1 4 2 4 - 2 = 2
P2 9 2 9 - 2 = 7
Total Holding: 9

Step-by-Step Execution:

Given: Total Resources (Tape Drives) = 12

Initial Available = Total - Holding = 12 - 9 = 3

  • Check P0: Needs 5. We have 3. (5 ≤ 3) ❌ False, Skip.
  • Check P1: Needs 2. We have 3. (2 ≤ 3) ✅ True! Execute P1.
    ➔ P1 finishes and releases its holding (2). New Available = 3 + 2 = 5
  • Check P2: Needs 7. We have 5. (7 ≤ 5) ❌ False, Skip.
  • Check P0 again: Needs 5. We have 5. (5 ≤ 5) ✅ True! Execute P0.
    ➔ P0 finishes and releases its holding (5). New Available = 5 + 5 = 10
  • Check P2 again: Needs 7. We have 10. (7 ≤ 10) ✅ True! Execute P2.
    ➔ P2 finishes and releases holding (2). Final Available = 10 + 2 = 12 (All restored!)
Safe State Sequence: < P1, P0, P2 >

Semaphores

Integer variables accessed only through two standard atomic operations: wait() and signal().

1. Binary Semaphore (Mutex)

Value is strictly 0 or 1. Used for solving critical section problems.

  • 1 : Lock is available (Out/Exit)
  • 0 : Lock is acquired (Entry/Blocked)

2. Counting Semaphore

Value can range over an unrestricted domain. Used to control access to a resource with multiple instances.

  • If value drops below 0 (-ve), entry is not available.
  • The absolute value of the negative number = number of blocked processes waiting in queue.
wait (P / Down)
Value = Value - 1
signal (V / Up)
Value = Value + 1

Memory Fragmentation

As processes are loaded and removed from memory, free RAM space gets broken into small, scattered pieces. This is called fragmentation.

1. Internal Fragmentation

Occurs when memory is divided into fixed-sized blocks. If a process requires less space than the allocated block, the leftover space inside the block is wasted.

Allocated Block Space (e.g., 4KB)
Process uses 3KB
1KB Wasted

2. External Fragmentation

Occurs when the total free memory is enough to satisfy a process request, but it is not contiguous (it's scattered). The OS cannot load the process.

✅ Solutions to External Fragmentation:
  • Compaction: Shuffle memory contents to group all free space together.
  • Paging/Segmentation: Allow a process's physical memory to be non-contiguous.

Paging Architecture

Paging avoids external fragmentation by splitting memory into fixed-size blocks.

  • Primary (Physical) Memory ➔ Divided into Frames
  • Secondary (Logical) Memory ➔ Divided into Pages
  • Golden Rule: Frame Size = Page Size
// Mathematical Formulas

Size of Physical Memory = Frame Size × No. of Frames

Size of Logical Memory = Page Size × No. of Pages


// Image Example Translation

No. of Pages = 64 = 2^6

Page Size = 4KB = (2^2 * 2^10) = 2^12 bytes

Logical Memory = 2^6 × 2^12 = 2^18 bytes

Effective Access Time (EAT)

When using a TLB (Translation Look-aside Buffer - a fast hardware cache), we calculate the average time to access memory.

EAT = Hit Ratio × (TLB + PM) + Miss Ratio × (TLB + 2*PM)

Example Problem from Image

Given: Hit Ratio = 80%, TLB access time = 15ns, Main Memory (PM) access time = 150ns.

// Note: Miss Ratio = (100% - 80%) = 20%

EAT = 0.80 * (15 + 150) + 0.20 * (15 + 2 * 150)

EAT = 0.80 * (165) + 0.20 * (15 + 300)

EAT = 132 + 0.20 * (315)

EAT = 132 + 63

EAT = 195 ns

* Why 2*PM on a miss? One access for the Page Table in memory, one access for the actual data in memory.

First-In, First-Out (FIFO)

Replaces the oldest page in memory. Simple to implement using a queue.

Least Recently Used (LRU)

Look at the PAST ⬅️

Replaces the page that has not been used for the longest period of time. It relies on the assumption that pages heavily used in the last few instructions will likely be used again.

String:701203
Frame 1:777222
Frame 2:-00000
Frame 3:--1113
Status:MissMissMissMiss(Evict 7)HITMiss(Evict 1)

When '3' arrives, looking back: '0' was just used, '2' was used before it, '1' was used longest ago. So, evict '1'.

Optimal Algorithm (OPT)

Look into the FUTURE ➡️

Replaces the page that will not be used for the longest period of time in the future. Guarantees the lowest possible page-fault rate.

String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3... (Extended for example)

When memory is [7, 0, 1] and '2' arrives:
Look forward: '0' is needed next, '1' is not seen in near future.
Evict 7 (or 1).

Reality Check: Impossible to implement in real OS because we cannot predict the future string of memory references. It is used as a benchmark to test other algorithms.
Seek Time Time to move head to desired track (cylinder). Most important to minimize!
Rotational Latency Time for desired sector to rotate under the read/write head.
Golden Fact "LOOK" algorithm usually provides the Minimum Head Movement.

Example Track Queue: [ 98, 183, 37, 122, 14, 124, 65, 67 ]

Current Head Position: 53 (Moving towards higher tracks initially). Total Cylinders: 0 to 199.

First Come First Serve (FCFS)

Services requests strictly in the order they arrive in the queue.

Path: 53 ➔ 98 ➔ 183 ➔ 37 ➔ 122 ➔ 14 ➔ 124 ➔ 65 ➔ 67

Total Head Movement is huge (wildly swinging back and forth). Very slow.

Shortest Seek Time First (SSTF)

Selects the request with the minimum seek time (closest track) from the current head position.

Path: 53 ➔ 65 ➔ 67 ➔ 37 ➔ 14 ➔ 98 ➔ 122 ➔ 124 ➔ 183

Massive improvement in speed over FCFS.

Con: Can cause starvation for requests far away from the head.

SCAN (Elevator Algorithm)

Head moves towards one end of the disk, servicing requests, touches the very end (199), then reverses direction and services the rest.

Path: 53 ➔ 65 ➔ 67 ➔ 98 ➔ 122 ➔ 124 ➔ 183 ➔ 199 (End) ➔ 37 ➔ 14

Fairer than SSTF, but going all the way to the extreme end when no request is there is wasteful.

Circular SCAN (C-SCAN)

Like SCAN, but when it hits the end, it immediately jumps to the absolute beginning (0) without servicing requests on the return trip, then continues scanning.

Path: 53 ➔ 65 ➔ 67 ➔ 98 ➔ ... ➔ 183 ➔ 199 ➔ Jump to 0 ➔ 14 ➔ 37

Provides a more uniform wait time than SCAN.

LOOK Minimum Movement

Smarter SCAN. It only goes as far as the last request in a direction before reversing. It does NOT touch the extreme ends.

Path: 53 ➔ 65 ➔ 67 ➔ 98 ➔ 122 ➔ 124 ➔ 183 (Last req, reverses here) ➔ 37 ➔ 14

This is the optimal practical algorithm to minimize head movement (as noted in cheat sheet!).

Circular LOOK (C-LOOK)

Smarter C-SCAN. Goes to the last request in the direction, then jumps to the lowest requested track (not 0), and continues.

Path: 53 ➔ 65 ➔ 67 ➔ ... ➔ 183 ➔ Jump to 14 ➔ 37
