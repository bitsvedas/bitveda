💻 Operating System (OS) — Complete Notes

Introduction, Types, Layered Architecture, Process Management, Scheduling, Threads & IPC

🏛️ Best Analogy
OS बिल्कुल एक सरकार (Government) की तरह है—खुद कोई सामान नहीं बनाती, बल्कि बाकी सब को काम करने का सही माहौल और संसाधन देती है!

1. Definition of Operating System

Operating System (OS) एक System Software है जो कंप्यूटर के User (उपयोगकर्ता) और Computer Hardware के बीच एक Interface (मध्यस्थ / पुल) का कार्य करता है।

बिना Operating System के कंप्यूटर केवल प्लास्टिक और धातु का एक डिब्बा (Dead Hardware) है। OS कंप्यूटर के सभी संसाधनों (CPU, RAM, Hard Disk, Keyboard, Printer) को प्रबंधित (Manage) करता है और यूज़र के प्रोग्राम्स (जैसे Chrome, MS Word, Games) को चलाने के लिए प्लेटफॉर्म देता है।
उदाहरण: Windows, Linux, macOS, Android, iOS, UNIX।

📐 Fig 1.1: Operating System as an Interface (Abstract View of Computer System)

2. Main Functions of Operating System

1. Process Management प्रोसेस बनाना (Create), रोकना, हटाना और CPU Scheduling द्वारा हर प्रोग्राम को CPU समय बांटना।
2. Memory Management RAM का कौन-सा हिस्सा खाली है और किस प्रोसेस को कितनी मेमोरी देनी है—इसका पूरा हिसाब रखना।
3. File Management डेटा को Files और Folders (Directories) के रूप में व्यवस्थित करना, सेव करना और एक्सेस कंट्रोल देना।
4. Device (I/O) Management Device Drivers की मदद से Keyboard, Mouse, Printer, Disk आदि हार्डवेयर को नियंत्रित करना।
5. Security & Protection Password, Authentication और Permissions के ज़रिए अनधिकृत (Unauthorized) एक्सेस से डेटा बचाना।
6. Error Detection & Accounting सिस्टम में आने वाली खराबी (Bugs/Errors) को पकड़ना और किस यूज़र ने कितने संसाधन उपयोग किए, ट्रैक करना।

4. Types of Operating Systems (OS के प्रकार)

📌 Exam Trick
B - M - T - D - R - E याद रखो:
Batch, Multiprogramming, Time-Sharing, Distributed, Real-Time, Embedded!

कार्य करने के तरीके और यूज़र की ज़रूरतों के आधार पर Operating Systems को 6 मुख्य श्रेणियों में बांटा जाता है:

1. Batch Operating System

इसमें यूज़र सीधे कंप्यूटर से बात (interact) नहीं करता। एक जैसे कामों (Jobs) का एक Batch (समूह) बनाकर Operator को दे दिया जाता है, जो उन्हें एक-एक करके कंप्यूटर में चलाता है।
कमी: CPU बहुत देर खाली (Idle) रहता है जब I/O चल रहा हो। उदाहरण: Payroll System, Bank Statements (IBM OS/360)।

2. Multiprogramming Operating System

इसका मुख्य उद्देश्य CPU Utilization को अधिकतम करना है। इसमें Main Memory (RAM) में एक साथ कई प्रोग्राम लोड रहते हैं। जैसे ही Program 1 किसी I/O (जैसे प्रिंटर या डिस्क) का इंतज़ार करता है, CPU तुरंत खाली बैठने के बजाय Program 2 को चलाने लगता है।

3. Time-Sharing (Multitasking) Operating System

यह Multiprogramming का ही उन्नत रूप है। इसमें हर प्रोसेस/यूज़र को एक बहुत छोटा निश्चित समय (Time Quantum, जैसे 10ms) दिया जाता है। CPU इतनी तेज़ी से सबके बीच स्विच करता है कि हर यूज़र को लगता है कि पूरा कंप्यूटर सिर्फ उसी के लिए चल रहा है।
उदाहरण: UNIX, Linux, Windows, macOS।

📐 Fig 2.1: Memory Layout (Multiprogramming) vs CPU Time Slicing (Time-Sharing)

4. Distributed Operating System

इसमें नेटवर्क के ज़रिए जुड़े हुए कई अलग-अलग कंप्यूटर (Nodes) मिलकर काम करते हैं, जिनके पास अपना-अपना CPU और Memory होती है—परंतु यूज़र को यह पूरा सिस्टम एक ही सिंगल कंप्यूटर जैसा दिखता है। यदि एक नोड खराब हो जाए, तो बाकी नोड्स काम जारी रखते हैं (Fault Tolerant)। उदाहरण: LOCUS, Amoeba।

5. Real-Time Operating System (RTOS)

जहाँ समय सीमा (Strict Deadline) सबसे महत्वपूर्ण हो—अर्थात् डेटा का उत्तर तय सेकंड/मिलीसेकंड के भीतर आना ही चाहिए। इसके 2 प्रकार होते हैं:

  • Hard Real-Time OS: थोड़ी सी भी देरी होने पर भयानक दुर्घटना या नुकसान हो सकता है। (उदा: Missile Control, Air Traffic Control, Pacemaker)।
  • Soft Real-Time OS: कभी-कभार हल्की देरी बर्दाश्त की जा सकती है। (उदा: Live Video Streaming, Online Gaming)।

6. Embedded Operating System

यह विशेष रूप से किसी एक ही विशिष्ट हार्डवेयर डिवाइस के लिए बनाया गया छोटा, हल्का और तेज़ OS होता है, जो अक्सर ROM/Flash Memory में स्टोर रहता है। उदाहरण: Smart TV, Washing Machine, Microwave, ATM, Car Infotainment (VxWorks, FreeRTOS, Embedded Linux)।

OS Type Primary Goal (मुख्य लक्ष्य) User Interaction Real-World Example

5. Layered Structure (Approach) of Operating System

🧅 Onion Analogy
Layered OS बिल्कुल एक प्याज (Onion) के छिलकों जैसा होता है—सबसे अंदर Hardware (Layer 0) और सबसे बाहर User Interface (Layer N)!

Layered Architecture ऑपरेटिंग सिस्टम को डिज़ाइन करने का एक मॉड्यूलर (Modular) तरीका है। इसमें पूरे OS को एक बड़े प्रोग्राम की तरह लिखने के बजाय कई अलग-अलग Layers (परतों) में बांट दिया जाता है, जहाँ हर परत एक के ऊपर एक रखी होती है।

मुख्य नियम (Golden Rule of Layered OS):
हर परत (Layer i) केवल अपने ठीक नीचे वाली परत (Layer i - 1) के फंक्शन्स और सेवाओं का उपयोग कर सकती है, और अपने ठीक ऊपर वाली परत (Layer i + 1) को सेवाएं प्रदान करती है। कोई भी परत सीधे किसी निचली परत को कूदकर (Skip करके) एक्सेस नहीं कर सकती।

📐 Fig 3.1: Layered Architecture of Operating System (Layer 0 to Layer 5)

प्रत्येक लेयर का विस्तृत विवरण (Layer-by-Layer Explanation)

Layer Name (नाम) मुख्य कार्य (Responsibilities)
Layer 0 Hardware सबसे भीतरी और बुनियादी स्तर। इसमें भौतिक उपकरण (CPU, RAM, Registers, Hard Disk, I/O Devices) होते हैं।
Layer 1 CPU Scheduling मल्टीप्रोग्रामिंग और प्रोसेस स्विचिंग को संभालता है। तय करता है कि किस प्रोसेस को कब CPU मिलेगा।
Layer 2 Memory Management प्रोसेस के लिए Main Memory (RAM) आवंटित करना, Paging और Virtual Memory को नियंत्रित करना।
Layer 3 I/O & Device Drivers हार्डवेयर डिवाइस (माउस, कीबोर्ड, प्रिंटर) के साथ कम्युनिकेशन और Buffering संभालना।
Layer 4 File System डेटा को फाइल्स और डायरेक्टरीज़ (Folders) में सेव करना, पढ़ना और सिक्योरिटी लागू करना।
Layer 5 User Interface (UI) सबसे बाहरी परत (Layer N) जहाँ यूज़र सीधे काम करता है (जैसे Windows GUI, Linux Terminal/Shell)।
✅ Advantages (फायदे):
1. Modularity: पूरा OS छोटे-छोटे हिस्सों में बंटा होता है, जिससे इसे बनाना और समझना आसान है।
2. Easy Debugging: लेयर-बाय-लेयर टेस्टिंग होती है। यदि Layer 2 में एरर आए, तो पता होता है कि गड़बड़ी सिर्फ Layer 2 में ही है।
3. Information Hiding: ऊपर की लेयर को यह जानने की ज़रूरत नहीं कि नीचे की लेयर अंदर से कैसे काम करती है।
❌ Disadvantages (कमियाँ):
1. Careful Layer Design: लेयर्स का सही क्रम तय करना कठिन है (जैसे: Memory Manager को Disk चाहिए, और Disk Driver को Memory!)।
2. Less Efficient (Overhead): यूज़र की एक रिक्वेस्ट को कई लेयर्स से गुज़रना पड़ता है, जिससे सिस्टम थोड़ा धीमा हो सकता है।

प्रमुख उदाहरण: THE Operating System (Edsger Dijkstra द्वारा 1968 में बनाया गया पहला प्रसिद्ध Layered OS), MULTICS, तथा UNIX / Windows NT (जो आंशिक रूप से Layered डिज़ाइन का उपयोग करते हैं)।

6. Kernel in Operating System (कर्नेल — OS का हृदय)

🚗 Best Analogy
अगर पूरा OS एक कार (Car) है, तो Kernel उसका Engine है! बिना कर्नेल के OS कुछ भी नहीं कर सकता।

Kernel (कर्नेल) ऑपरेटिंग सिस्टम का सबसे महत्वपूर्ण और केंद्रीय भाग (Core Component) है। जब कंप्यूटर ऑन (Boot) होता है, तो यह सबसे पहले RAM में लोड होता है और सिस्टम बंद होने तक लगातार मेमोरी में मौजूद रहता है।

कर्नेल Applications (Software) और Hardware (CPU, RAM, Disk) के बीच सीधा संपर्क बनाता है। जब कोई ऐप (जैसे Chrome या Music Player) किसी हार्डवेयर का उपयोग करना चाहता है, तो वह सीधे हार्डवेयर को नहीं छू सकता—वह System Call के ज़रिए कर्नेल से अनुरोध करता है।

Kernel के मुख्य कार्य (Main Functions of Kernel)

1. Process & CPU Management प्रोसेस को CPU आवंटित करना, Context Switching करना और मल्टीटास्किंग चलाना।
2. Memory Management किस प्रोग्राम को RAM में कितनी जगह मिलेगी और डेटा सुरक्षित कैसे रहेगा, यह तय करना।
3. Device Management Device Drivers के माध्यम से कीबोर्ड, माउस, प्रिंटर और हार्ड डिस्क को नियंत्रित करना।
4. System Calls & Security User Mode से आने वाली रिक्वेस्ट को सुरक्षित तरीके से Kernel Mode में पूरा करना।

User Mode vs Kernel Mode (Dual-Mode Operation)

सिस्टम को क्रैश या हैकिंग से बचाने के लिए CPU दो मोड में काम करता है:

  • User Mode (सामान्य मोड): इसमें यूज़र के सामान्य ऐप्स (Browser, MS Word, Games) चलते हैं। इन्हें हार्डवेयर का सीधा एक्सेस नहीं होता।
  • Kernel Mode (सुपरवाइज़र मोड): इसमें OS Kernel चलता है। इसे कंप्यूटर के पूरे हार्डवेयर और मेमोरी का पूर्ण अधिकार (Full Privilege) होता है। जब यूज़र ऐप को हार्डवेयर चाहिए होता है, तो वह System Call भेजकर Kernel Mode में स्विच करता है।
📐 Fig 4.1: Role of Kernel & Types (Monolithic vs Microkernel Architecture)

Types of Kernel (कर्नेल के मुख्य प्रकार)

Kernel Type संरचना और कार्यप्रणाली (Architecture) फायदा / कमी Examples
1. Monolithic Kernel OS की सभी सेवाएं (File System, Drivers, Scheduling, Memory) एक ही बड़ी Kernel Space में चलती हैं। फायदा: बहुत तेज़ गति।
कमी: एक ड्राइवर क्रैश हो तो पूरा OS क्रैश हो जाता है।		 Linux, UNIX, MS-DOS
2. Microkernel कर्नेल में केवल सबसे ज़रूरी सेवाएं (IPC, Basic Scheduling) होती हैं; बाकी सब User Space में चलता है। फायदा: अधिक सुरक्षित व स्थिर।
कमी: बार-बार IPC के कारण थोड़ा धीमा।		 Minix, QNX, Mach
3. Hybrid Kernel यह Monolithic की तेज़ गति और Microkernel की सुरक्षा/मॉड्यूलैरिटी—दोनों का मिश्रण है। फायदा: बेहतरीन परफॉर्मेंस और स्थिरता का संतुलन। Windows NT/10/11, macOS

अन्य विशेष प्रकार: Nanokernel (अत्यंत सूक्ष्म कर्नेल, जो सिर्फ हार्डवेयर एब्स्ट्रैक्शन देता है) तथा Exokernel (जो ऐप्स को सीधे हार्डवेयर मैनेज करने की छूट देता है)।

7. Process Management: Process Concept

📖 Program vs Process
Program = Recipe Book (Passive, डिस्क पर सेव)
Process = खाना बनाना शुरू करना (Active, RAM में चल रहा!)

जब कोई प्रोग्राम हार्ड डिस्क में पड़ा होता है, तो वह एक Passive Entity है। लेकिन जैसे ही आप उस पर डबल-क्लिक करते हैं और वह RAM में लोड होकर चलने लगता है, उसे Process (A Program in Execution) कहते हैं।

मेमोरी में Process के 4 भाग: (1) Text Section: प्रोग्राम का कोड, (2) Data Section: Global Variables, (3) Heap: Dynamic Memory (रन-टाइम पर बढ़ती है), (4) Stack: Local Variables व Function Calls।

Process Control Block (PCB): OS हर प्रोसेस का एक "Identity Card" बनाता है जिसे PCB कहते हैं। इसमें Process ID (PID), Current State, Program Counter (अगला निर्देश), CPU Registers और Memory Limits सेव रहते हैं।

📐 Fig 5.1: Process Memory Layout & Process Control Block (PCB)

Process States (प्रोसेस की 5 अवस्थाएं)

अपने जीवनकाल (Lifecycle) में एक प्रोसेस 5 मुख्य अवस्थाओं से गुज़रता है:

📐 Fig 5.2: 5-State Process State Transition Diagram
  1. New: प्रोसेस अभी नया-नया बनाया (Create) जा रहा है।
  2. Ready: प्रोसेस RAM में आ चुका है और CPU मिलने का इंतज़ार कर रहा है।
  3. Running: प्रोसेस के निर्देश (Instructions) वर्तमान में CPU पर चल रहे हैं।
  4. Waiting (Blocked): प्रोसेस किसी I/O काम (जैसे प्रिंटिंग या यूज़र इनपुट) के पूरा होने का इंतज़ार कर रहा है।
  5. Terminated: प्रोसेस का काम पूरा हो गया है और OS उसे मेमोरी से हटा रहा है।

8. Process Scheduling (CPU Scheduling) — Detailed

जब Ready Queue में कई प्रोसेस तैयार खड़े हों, तो किस प्रोसेस को पहले CPU दिया जाए—यह निर्णय लेने की प्रक्रिया CPU Scheduling कहलाती है। यह काम Short-Term Scheduler करता है।

⭐ Exam Rule
अगर प्रश्न में Arrival Time (AT) अलग-अलग हो, तो हमेशा पहले देखो कि उस समय (t) तक कौन-कौन से प्रोसेस आ चुके हैं! जो आया ही नहीं, उसे CPU नहीं मिल सकता।
  • Non-Preemptive Scheduling: एक बार प्रोसेस को CPU मिल गया, तो वह पूरा खत्म होने या I/O पर जाने से पहले CPU नहीं छोड़ता।
  • Preemptive Scheduling: OS बीच में ही किसी चलते हुए प्रोसेस से CPU छीनकर ज़्यादा ज़रूरी प्रोसेस को दे सकता है (जैसे Round Robin, SRTF)।
📌 Important Scheduling Terms & Formulas (रट लो!):
• AT (Arrival Time): प्रोसेस Ready Queue में किस समय आया।
• BT (Burst Time): प्रोसेस को CPU पर पूरा चलने के लिए कुल कितना समय चाहिए।
• CT (Completion Time): प्रोसेस Gantt Chart के अनुसार किस समय समाप्त हुआ।
• TAT (Turnaround Time) = CT - AT   (सिस्टम में आने से खत्म होने तक का कुल समय)
• WT (Waiting Time)     = TAT - BT (Ready Queue में इंतज़ार का कुल समय)

1. FCFS (First Come, First Serve) — Detailed

सिद्धांत (Working): यह सबसे सरल Non-Preemptive एल्गोरिदम है जो FIFO (First-In, First-Out) कतार की तरह काम करता है। जिसका Arrival Time (AT) सबसे कम होता है (जो पहले आता है), उसे पहले CPU मिलता है।

Numerical Question: मान लीजिए 4 प्रोसेस नीचे दिए गए Arrival Time और Burst Time के साथ आते हैं (जहाँ P1 का BT = 5 है):

❌ कमी (Convoy Effect): बड़ा प्रोसेस पहले आ जाए तो छोटे प्रोसेस को बहुत इंतज़ार करना पड़ता है।

2. SJF (Shortest Job First — Non-Preemptive) — Detailed

सिद्धांत (Working): जो प्रोसेस Ready Queue में आ चुके हैं, उनमें से जिसका Burst Time (BT) सबसे कम है, उसे पहले CPU दिया जाता है। यह सबसे कम Average Waiting Time देता है। (इसका Preemptive रूप SRTF कहलाता है)।

3. Priority Scheduling (Non-Preemptive) — Detailed

सिद्धांत (Working): हर प्रोसेस के साथ एक Priority Number जुड़ा होता है। Ready Queue में मौजूद प्रोसेस में से जिसकी Priority सबसे अधिक हो (यहाँ छोटा नंबर = High Priority, अर्थात् 1 सबसे ऊँचा), उसे पहले CPU मिलता है।

समाधान (Aging): लो-प्रायोरिटी प्रोसेस को Starvation से बचाने के लिए, लंबे इंतज़ार के बाद OS धीरे-धीरे उसकी Priority बढ़ाता जाता है।

4. Round Robin (RR — Preemptive) — Detailed

सिद्धांत (Working): यह Time-Sharing OS का सबसे लोकप्रिय एल्गोरिदम है। हर प्रोसेस को एक तय समय Time Quantum (q) के लिए CPU मिलता है। यदि प्रोसेस उस समय में पूरा न हो, तो उसे रोककर (Preempt करके) वापस Ready Queue के अंत में भेज दिया जाता है।

9. Threads (थ्रेड्स — Lightweight Process)

📝 MS Word Example
MS Word एक Process है, और उसमें एक साथ चलने वाले Typing, Spell-Check और Auto-Save अलग-अलग Threads हैं!

Thread किसी प्रोसेस के अंदर CPU Execution की सबसे छोटी इकाई है। इसे Lightweight Process भी कहते हैं क्योंकि एक ही प्रोसेस के सभी थ्रेड्स उसका Code, Data और Open Files आपस में शेयर करते हैं।

हालाँकि, हर थ्रेड के पास अपना अलग Thread ID, Program Counter, Registers और Stack होता है।

📐 Fig 8.1: Single-Threaded vs Multi-Threaded Process Architecture
  • User-Level Threads (ULT): इन्हें यूज़र की Thread Library मैनेज करती है (Kernel को इनकी खबर नहीं होती)। ये बहुत तेज़ बनते हैं, पर यदि एक थ्रेड ब्लॉक हो तो पूरा प्रोसेस रुक जाता है।
  • Kernel-Level Threads (KLT): इन्हें सीधे OS Kernel मैनेज करता है। ये थोड़े धीमे बनते हैं, लेकिन एक थ्रेड के ब्लॉक होने पर बाकी थ्रेड्स Multi-core CPU पर चलते रहते हैं।

Multithreading के फायदे: (1) Responsiveness (ऐप हैंग नहीं होता), (2) Resource Sharing (मेमोरी बचती है), (3) Economy (नया प्रोसेस बनाने से सस्ता), (4) Scalability (Multi-core CPU का पूरा लाभ)।

10. Inter-Process Communication (IPC)

सिस्टम में चलने वाले प्रोसेस दो तरह के होते हैं—Independent (जो दूसरों को प्रभावित नहीं करते) और Cooperating (जो एक-दूसरे से डेटा शेयर करते हैं)। Cooperating प्रोसेस को आपस में डेटा आदान-प्रदान और सिंक्रोनाइज़ करने के लिए जिस तकनीक की ज़रूरत होती है, उसे Inter-Process Communication (IPC) कहते हैं।

IPC के दो मुख्य मॉडल (Models) होते हैं: 1. Shared Memory और 2. Message Passing।

📐 Fig 8.2: Two Fundamental IPC Models — Shared Memory vs Message Passing
Basis (आधार) Shared Memory Message Passing
कार्यप्रणाली दोनों प्रोसेस एक ही कॉमन RAM हिस्से (Buffer) में डेटा लिखते और पढ़ते हैं। प्रोसेस send() और receive() सिस्टम कॉल द्वारा Kernel के माध्यम से मैसेज भेजते हैं।
गति (Speed) बहुत तेज़ (Fast) — सेटअप के बाद बार-बार Kernel की ज़रूरत नहीं। अपेक्षाकृत धीमा — हर मैसेज पर System Call (Kernel हस्तक्षेप) होता है।
उपयोग (Best For) एक ही कंप्यूटर में बड़े डेटा का तेज़ आदान-प्रदान। छोटा डेटा और अलग-अलग कंप्यूटर (Distributed Network) के बीच कम्युनिकेशन।
