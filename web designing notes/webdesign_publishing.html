Introduction to Web Publishing

Prepared by: Aakash Sen (Self Study Group Hindi-English Blend Edition)

सरल शब्दों में, Web Publishing का अर्थ है अपनी फाइलों (HTML, CSS, JavaScript, Images) को लोकल कंप्यूटर से निकाल कर एक सार्वजनिक वेब सर्वर पर अपलोड करना, ताकि पूरी दुनिया में कोई भी व्यक्ति उसे इंटरनेट के ज़रिए खोल सके।

💡 Analogy Time: मान लो तुमने अपने घर पर एक डायरी (Website) लिखी। जब तक डायरी घर पर आलमारी में बंद है, वह तुम्हारा Local Storage है। पर अगर तुम उसे प्रिंटिंग प्रेस भेज कर हर दुकान में रखवा दो (Web Server), तो वह Publish हो गई!

1. Creating & Saving the Website

एक वेबसाइट बनाना हमारा पहला कदम होता है। हम कोडिंग के लिए Frontend Technologies का प्रयोग करते हैं:

  • HTML (Markup Layout): वेबसाइट का बुनियादी ढांचा (Structure) तैयार करता है।
  • CSS (Styling): उसे सुंदर रंग, मार्जिन, बॉर्डर और फॉन्ट प्रदान करता है।
  • JavaScript (Interactivity): पेज में जान डालता है (Dynamic behavior जैसे क्लिक होने पर पॉप-अप आना)।

Saving Rules (फाइलें सुरक्षित करने के कड़े नियम):

अपने कंप्यूटर पर सभी फाइलों को एक Root Folder में व्यवस्थित रखना होता है। होमपेज वाली मुख्य फाइल का नाम हमेशा `index.html` ही होना चाहिए।

Warning Zone!

कभी भी होमपेज का नाम MyHome.html या main.html मत रखना!
Web Servers स्वतः केवल index.html को ही ढूंढते हैं। अगर यह नहीं मिली तो 403 Forbidden या Directory list एरर दिखेगा!

Standard Folder Directory Tree: 📁 My_Web_Project/ (Root Directory)
    ├── 📄 index.html <-- (यह मुख्य दरवाजा है)
    ├── 📄 about.html
    ├── 📁 css/
    │    └── 📄 style.css
    ├── 📁 js/
    │    └── 📄 main.js
    └── 📁 images/
         └── 🖼️ logo.png

2. Web Hosting & Hosting Considerations

वेबसाइट की फाइलों को सुरक्षित रखने के लिए जिस भारी-भरकम कंप्यूटर (Server Machine) को किराए पर लिया जाता है, उस सेवा को Web Hosting कहते हैं। होस्टिंग लेते समय निम्नलिखित 4 बातों (Considerations) पर कड़ाई से ध्यान देना चाहिए:

A. Storage Space (डिस्क स्टोरेज)

आपकी वेबसाइट की इमेजेस, फाइलों और डेटाबेस का साइज कितना है? क्या होस्टिंग कंपनी आपको SSD (Solid State Drive) दे रही है जो कि HDD से 10 गुना तेज़ होती है?

B. Bandwidth (बैंडविड्थ सीमा)

यह वह डेटा है जो वेबसाइट और विज़िटर के बीच ट्रांसफर होता है।
Formula: Page Size × No. of Monthly Visitors. अगर विज़िटर ज़्यादा हैं तो आपको Unlimited Bandwidth वाली होस्टिंग लेनी होगी।

C. Server Uptime (सर्वर अपटाइम)

यह प्रतिशत में आंका जाता है। होस्टिंग सर्वर साल भर में कितने प्रतिशत समय ऑनलाइन रहा। एक अच्छी होस्टिंग सर्विस का अपटाइम न्यूनतम 99.9% होना ही चाहिए।

D. SSL & Security

आपकी साइट का पता सुरक्षित होना चाहिए। इसके लिए SSL Certificate आवश्यक है ताकि URL के आगे सुरक्षित ताल https:// दिखाई दे।

Types of Hosting Plans (होस्टिंग के मुख्य प्रकार):

1. Shared Hosting (साझा होस्टिंग):

बिल्कुल एक हॉस्टल के कमरे की तरह जहां एक ही कंप्यूटर (Server) के रिसोर्सेज को कई अलग-अलग वेबसाइट्स आपस में साझा करती हैं।
Pro: बहुत सस्ती। Con: अगर एक साइट पर अत्यधिक ट्रैफिक आता है, तो बाकी सारी साइट्स भी स्लो हो जाती हैं।

2. Dedicated Hosting (समर्पित होस्टिंग):

पूरा का पूरा कंप्यूटर सर्वर सिर्फ आपकी वेबसाइट के लिए रिज़र्व होता है। यह अपना आलीशान स्वतंत्र बंगला खरीदने जैसा है।
Pro: सुपरफास्ट स्पीड और पूरी प्राइवेसी। Con: बहुत ज़्यादा महंगी।

3. Cloud Hosting (क्लाउड होस्टिंग):

आपकी साइट किसी एक सिंगल कंप्यूटर पर नहीं बल्कि पूरी दुनिया में फैले दर्जनों कंप्यूटर्स के "वर्चुअल ग्रिड" पर काम करती है। यदि एक सर्वर क्रैश हो जाए, तो दूसरा तुरंत उसे संभाल लेता है।

3. Choosing Web Servers

Web Server असल में वह स्पेशल कंप्यूटर और उसपर चलने वाला सॉफ्टवेयर इंजन है जो यूजर के वेब ब्राउज़र (Client) से भेजी गई HTTP Request को सुनता है और सही HTML पेज को वापस HTTP Response के रूप में वापस भेजता है।

Server Engine Name Best Known For Ideal Usage Scenario
Apache HTTP Server अत्यंत पुराना, फ्लेक्सिबल, ओपन-सोर्स और विश्वसनीय। (.htaccess सपोर्ट) Shared hosting and Standard PHP (WordPress) sites.
Nginx (Engine-X) बेहद हल्का और सुपरफास्ट। लाखों पैरेलल रिक्वेस्ट झेलने में सक्षम। Reverse Proxy and High-Traffic modern Node.js apps.
Microsoft IIS (Internet Information Services) माइक्रोसॉफ्ट विंडोज़ सर्वर के साथ इन-बिल्ट आता है। Enterprise scale applications built with ASP.NET framework.

4. Domain Name Registration & DNS Resolution

इंटरनेट पर हर एक सर्वर का एक यूनिक नंबर आधारित एड्रेस होता है जिसे IP Address (जैसे: `172.217.16.142`) कहते हैं। लेकिन इंसानी दिमाग के लिए इसे याद रखना असंभव है।

इसलिए हम शब्दों वाले पते यानी Domain Name (जैसे: `google.com`) का प्रयोग करते हैं।

DNS (Domain Name System) इंटरनेट की फोनबुक है जो इन नाम वाले डोमेन एड्रेस को वापस सर्वर के आईपी एड्रेस में कनवर्ट करती है।

DNS Resolution Steps (काम कैसे करता है):

  1. यूजर ने ब्राउज़र में टाइप किया: www.mysite.com
  2. ब्राउज़र सबसे पहले आपके इंटरनेट सर्विस प्रोवाइडर (ISP) के पास बने DNS Resolver से पूछता है।
  3. रिज़ॉल्वर सबसे ऊपर बैठे Root Servers (.) से पूछता है कि .com कहाँ मिलेगा?
  4. रूट सर्वर उसे TLD (Top Level Domain) Server का रास्ता बताता है।
  5. TLD सर्वर आगे Authoritative Nameserver का पता देता है जो उस विशेष डोमेन के असली आईपी पते की चाबी रखता है।
  6. अंततः IP पता ब्राउज़र को मिलता है, ब्राउज़र सर्वर से कनेक्ट होता है, और वेबसाइट लोड होती है!

DNS Analogy

मानो तुम किसी दोस्त के घर जाना चाहते हो। तुम्हें उसका नाम "आकाश" याद है, लेकिन घर की लोकेशन नहीं पता।

तुम अपनी Phonebook (DNS) खोलते हो और "आकाश" पर क्लिक करते हो। फोनबुक उसका मोबाइल नंबर (IP Address) डायल कर देती है। यही DNS का मूलभूत काम है!

5. Practical Guide: Steps to Host a Website

आइए अब उस वास्तविक प्रक्रिया को देखते हैं जिसका उपयोग करके हम अपनी कोडिंग की फाइलों को लोकल मशीन से क्लाउड सर्वर पर भेज कर लाइव करते हैं। इसे 6 व्यवस्थित चरणों में पूरा किया जा सकता है:

1
Root Directory Preparation (फाइलों को संजोना)

अपने कंप्यूटर पर सभी HTML, CSS, JS और Images को एक मुख्य प्रोजेक्ट फोल्डर (Root Folder) में सहेजें। ध्यान दें कि मुख्य पेज का नाम अनिवार्यतः index.html होना चाहिए और सभी फाइलों के इंटरनल पाथ (internal paths) "Relative" होने चाहिए, न कि आपके C: drive का लोकल एड्रेस!

2
Buy Domain & Hosting (डोमेन व स्पेस खरीदना)

किसी नामी डोमेन रजिस्ट्रार (जैसे Namecheap, GoDaddy) से जाकर अपनी पसंद का डोमेन एड्रेस खरीदें। साथ ही होस्टिंग सर्विस प्रदाता से अपनी साइट के डेटा साइज के अनुसार क्लाउड स्पेस खरीदें।

3
Configure Nameservers (डोमेन पॉइंटिंग)

अपने डोमेन की सेटिंग्स में जाएं। वहां पुराने डिफ़ॉल्ट नेमसर्वर्स को हटाएं और अपनी होस्टिंग कंपनी द्वारा प्रदान किए गए नेमसर्वर्स (जैसे: ns1.hostingprovider.com) को पेस्ट करें। यह आपके डोमेन को सही सर्वर कंप्यूटर से जोड़ता है।

4
Connect via FTP Client (सर्वर से संपर्क स्थापित करना)

अपने लोकल पीसी पर **FileZilla** या **WinSCP** सॉफ्टवेयर इंस्टॉल करें। ऊपर दिए गए फ़ील्ड में अपने सर्वर का IP, FTP यूजरनेम, पासवर्ड, और पोर्ट नंबर 21 दर्ज करके Quickconnect पर क्लिक करें।

5
Locate public_html & Upload (फाइलें अपलोड करना)

कनेक्शन होने पर सर्वर वाले हिस्से (दाहिनी तरफ) में आपको `public_html` या `www` फोल्डर दिखेगा। इस फोल्डर को खोलें, और अपने लोकल कंप्यूटर की सभी फाइलों को ड्रैग करके सर्वर के इस फोल्डर में अपलोड कर दें।

6
Verifying the Live Website (सत्यापन)

अब किसी भी मोबाइल या कंप्यूटर पर अपना डोमेन नेम टाइप करें (उदा: www.yourdomain.com)। बधाई हो, आपकी खुद की बनाई हुई वेबसाइट अब पूरे विश्व के सामने ऑनलाइन लाइव हो चुकी है!

6. FTP (File Transfer Protocol) Software

अपने लोकल कंप्यूटर से वेब फाइलों को इंटरनेट के रिमोट सर्वर पर बिना किसी झंझट के अपलोड और डाउनलोड करने की प्रक्रिया को File Transfer Protocol (FTP) कहा जाता है।

इसके लिए एक विशेष यूजर इंटरफेस सॉफ्टवेयर चाहिए जिसे **FTP Client** कहते हैं।

लोकप्रिय FTP सॉफ्टवेयर्स (Popular Clients):

  • FileZilla: पूरी तरह ओपन-सोर्स, मुफ्त और सबसे लोकप्रिय सॉफ्टवेयर।
  • WinSCP: मुख्य रूप से विंडोज़ यूजर्स के लिए बनाया गया सुरक्षित FTP क्लाइंट।
  • Cyberduck: मैकओएस (macOS) यूजर्स के लिए बेहतरीन विजुअल और सुंदर इंटरफेस।

Tech Note: Connection Ports

कनेक्शन को सुरक्षित और सुचारू रखने के लिए पोर्ट्स का ज्ञान होना आवश्यक है:

💻 Port 21: अनएन्क्रिप्टेड FTP के लिए इस्तेमाल होता है।
🛡️ Port 22: **SFTP (SSH File Transfer Protocol)** के लिए होता है जो पूर्णतः सुरक्षित और एन्क्रिप्टेड है।

7. Add Website on Search Engines

वेबसाइट के लाइव होने के बावजूद भी वह गूगल पर सर्च करने से नहीं मिलेगी क्योंकि सर्च इंजन के पास अभी तक आपकी साइट के बारे में कोई जानकारी दर्ज नहीं है। इसके लिए हमें वेबसाइट को गूगल के डायरेक्टरी डेटाबेस में दर्ज कराना होता है।

Google Search Console:

यह गूगल की मुफ्त सेवा है जहां आपको अपने डोमेन ओनरशिप का सत्यापन करना होता है। इसके बाद गूगल का स्वचालित क्रॉलर रोबोट (जिसे Googlebot या Crawler / Spider कहते हैं) आपके वेब पेजों की हर एक लिंक को डीपली पढ़ना शुरू करता है।

Sitemap.xml Creation:

अपनी साइट के सभी एक्टिव लिंक्स की एक XML लिस्ट फाइल (सिटमैप) बनाएं और इसे सर्च कंसोल में अपलोड करें। यह फ़ाइल गूगल बोट्स के लिए एक मैप/नक्शे का काम करती है ताकि वह बिना किसी त्रुटि के हर पेज को आसानी से ट्रैक कर सके।

Indexing Process (इंडेक्सिंग):

क्रॉल करने के बाद जब गूगल आपके पेज के कंटेंट से संतुष्ट हो जाता है तो वह उसे अपने लाइब्रेरी रिकॉर्ड यानी **Google Index** में शामिल कर लेता है। इसी के बाद आपकी साइट कीवर्ड्स सर्च करने पर सर्च पेजों (SERP) पर दिखाई देने लगती है।

8. Issues in Website Creation & Maintenance

एक बार वेबसाइट पब्लिश होने के बाद डेवलपर की ज़िम्मेदारी खत्म नहीं हो जाती, असल में असली काम वहीं से शुरू होता है! वेबसाइट को हमेशा सुरक्षित, तेज, और सुचारू बनाए रखने के लिए मुख्य चुनौतियों का सामना करना पड़ता है:

A. Broken Links (टूटे हुए लिंक्स)

भविष्य में किसी पेज का URL बदलने या फ़ाइल डिलीट होने से यूजर के सामने निराशाजनक 404 Not Found जैसी एरर आ जाती है। इसके समाधान के लिए लगातार चेकिंग और 301 रिडायरेक्शन की आवश्यकता होती है।

B. Cross-Browser Compatibility

कई बार वेबसाइट क्रोम (Chrome) ब्राउज़र पर तो बिल्कुल परफेक्ट दिखती है, पर सफारी (Safari) या ओपेरा (Opera) पर उसका लेआउट बिखर जाता है। इसे दूर करने के लिए लगातार क्रॉस-ब्राउज़र टेस्टिंग करनी होती है।

C. Mobile Responsiveness

यूजर आपकी वेबसाइट को टीवी स्क्रीन, बड़ी एलसीडी मॉनिटर, टैबलेट या एक छोटे से मोबाइल पर भी खोल सकते हैं। वेबसाइट का लेआउट स्क्रीन साइज के अनुसार एडजस्ट होना चाहिए (Responsive Web Design via Media Queries)।

D. Security Patches & Spam

वेब सर्वर्स पर लगातार रोबोटिक डीडीओएस हमले और मालवेयर अटैक का खतरा बना रहता है। इससे बचने के लिए सुरक्षा प्लगइन्स, फ़ायरवॉल इंस्टॉल करना, डेटाबेस बैकअप रखना और हर सॉफ्टवेयर को अपडेट रखना बेहद आवश्यक है।

Quick Revision Checklist

Exam-Time Quick Revision Terms

📌 index.html: वेब सर्वर का डिफ़ॉल्ट होमपेज जो ब्राउज़र रिक्वेस्ट पर स्वतः लोड होता है।
📌 DNS: नाम वाले डोमेन को सर्वर के आईपी एड्रेस (संख्या) में बदलने वाली प्रणाली।
📌 FTP: फाइलों को लोकल सिस्टम से इंटरनेट सर्वर पर ट्रांसफर करने का मुख्य प्रोटोकॉल।
📌 Googlebot: गूगल का वेब क्रॉलर स्पाइडर जो नए वेब पेजों को सर्च करता है।
📌 Sitemap: आपकी संपूर्ण वेबसाइट के एक्टिव वेब पेजों का एक XML आधारित मानचित्र।
📌 SSL (https): डेटा ट्रांसफर को एन्क्रिप्ट कर वेबसाइट को हैकर्स से सुरक्षित रखने वाला डिजिटल सर्टिफिकेट।
